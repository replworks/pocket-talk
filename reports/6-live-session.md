# §6 라이브 세션 실측 — 48턴 (지연 · 배터리 · 발열)

- 실행일: 2026-10-27 01:27–01:40 (Asia/Seoul), **13분 7초**
- 측정자: 사용자(사람) — 실기기에서 실제로 말함
- 기기: iPhone 16, iOS 27.0.1, Apple 온디바이스 모델
- 결과: **발화 종료 → AI 음성 시작 p50 2,545ms.** 48턴 전부 1.5초 기준을 넘었다. 배터리·발열은 13분 동안 변화 없음.

## 1. 방법

앱의 라이브 탭에서 세션을 시작하고, 매 턴 `발화 시작` → 영어로 말하기 → `발화 완료`를 반복했다.
앱이 턴마다 `live-*.jsonl`에 세 가지 시각을 기록한다.

| 필드 | 기준 시각 |
| --- | --- |
| `utteranceEndToRecognitionMilliseconds` | `발화 완료` 버튼 → 최종 인식 결과 |
| `utteranceEndToFirstTokenMilliseconds` | `발화 완료` → 모델 첫 토큰 |
| `utteranceEndToAudioStartMilliseconds` | `발화 완료` → TTS 첫 오디오 |

원본: `eval/results/live-device-48turns.jsonl` (48 `live_turn` + 1 `session`)

## 4. 해석

1. **지연 기준은 명확히 미달이다.** 48턴 중 한 번도 1.5초 안에 음성이 시작되지 않았다.
   TASKS.md 기준("1.5초 이내, 이상적으론 1초 안팎")과 큰 차이다.
2. 병목은 TTS(358ms)나 인식(69ms)이 아니라 **모델 프리필**이다. 턴당 새 세션을 만들어
   캐시 입력이 항상 0이고, 컨텍스트가 길어질수록 프리필이 선형으로 늘어난다(2.0초 → 2.9초).
3. 개선 여지(아직 실행하지 않음):
   - 세션/프리픽스 재사용으로 프리필 제거 → 실측 캐시 재사용률 확인 필요
   - 첫 문장이 나온 뒤 TTS를 먼저 시작(문장 단위 스트리밍 합성)
   - 시스템 프롬프트·요약 길이 축소
4. 지연을 줄여도 1.5초는 빡빡하다. 온디바이스 3B급에서 2초대가 현실적이라면,
   **기준을 2.5~3초로 조정할지** 아니면 클라우드 하이브리드로 갈지가 §7의 핵심 판단이 된다.

## 6. UNVERIFIED

- 배터리가 시작/종료 모두 100%라 충전 중이었는지 알 수 없다. 발열·배터리 판정에는 부족하다.
- 한 사람, 한 번의 세션이다. 말하는 속도·문장 길이에 따라 인식/응답 시간이 달라진다.
- `발화 완료` 버튼을 누른 시각을 발화 종료로 쓴다. 실제 말이 끝난 시각과는 차이가 있다.
