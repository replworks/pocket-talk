# §5 30턴 컨텍스트 관리 — 실행 기록

- 실행일: 2026-10-27 (Asia/Seoul)
- 범위: 34턴 가상 대화를 실제 온디바이스 모델로 4가지 컨텍스트 정책에 대해 실행, 기억 상실 지점 측정
- 결과: 요약 접기(`recentTurns 8` + 400자 요약)에서 8개 사실 중 7개를 잃었다.
  `recentTurns 64`로 바꾸면 **8/8 유지**되고, 34턴 전체가 1,510 입력 토큰이라 8192 컨텍스트에 그냥 들어간다.
- 후속 조치: `ContextManager` 기본값과 앱 정책을 **`maxTokens 7000 / recentTurns 64`**로 변경하고 같은 스크립트로 재검증했다(8/8).

## 1. 실험 설계

같은 스크립트 `eval/long_conversation.json` (34턴, 사실 8개)을 정책만 바꿔 실행했다.

| 정책 | `recentTurns` | `maxTokens` | 의도 |
| --- | --- | --- | --- |
| `요약 없음` | 100 | 8,000 | 접기 없이 전체 유지 (기준선) |
| `기본 64`(채택) | 64 | 7,000 | 변경 후 기본값 |
| `요약 8턴`(이전 기본) | 8 | 7,680 | 기존 기본값 |
| `요약 700` | 8 | 700 | 예산 압박 |

**중요한 단위**: `recentTurns`는 턴(교환)이 아니라 **메시지 수**다. 사용자+AI 메시지가 쌍으로 쌓이므로
`8`은 4교환, `64`는 32교환을 유지한다. (이 단위를 턴으로 착각하면 "8턴 유지"라고 오해하게 된다.)

- 모델: **Apple 온디바이스 모델**(시뮬레이터, iOS 27.0 런타임, `iPhone 16 (iOS 27)`)
- 실행: 시뮬레이터 UI 테스트가 앱의 `장기 대화 실행`을 정책별로 탭
- 측정: 턴별 추정/실측 토큰, 요약 시작 턴, 지연, 8개 기억 프로브

프로브: 이름(Jina, 턴0→9), 도시(Busan, 0→11), 직업(nurse, 1→15), 여동생(Mina, 2→19),
약속(Saturday, 5→22), 음식(kimchi, 7→24), 개(Bori, 13→27), 공부시간(hour, 18→29).

## 3. 원인 (모델이 아니라 요약기)

`EvalRunner --replay`로 실제 응답을 `ContextManager`에 다시 넣어, 그 턴의 요약 내용을 확인했다.

| 정책 | 턴 | 요약(400자)에 남은 사실 |
| --- | --- | --- |
| 요약 8턴 | 9 | jina, mina |
| 요약 8턴 | 11 | jina, saturday |
| 요약 8턴 | 15 | jina |
| 요약 8턴 | 29 | jina |
| 기본 64 | 22 | (요약 없음 — 32턴까지 원문 유지) |

`ExtractiveSummarizer`는 400자를 넘으면 **최신 쪽을 남기고 앞을 버린다.** 그래서 요약이 "최근 4~5턴"으로
미끄러지고, 초반 사실이 요약에서도 사라진다. 요약 8턴에서 잃은 7건은 **모두 요약에 사실이 없던 경우**였다
(모델이 요약에 있는 사실을 무시한 경우는 0건).

## 4. 판정에 중요한 부작용: 지어냄

`recentTurns 24` 중간 실험(1회)에서 여동생 이름을 **`Minsoo`**라고 답했다. 스크립트의 이름은 `Mina`다.
요약에서 사실이 사라진 자리를 모델이 그럴듯하게 메우는, TASKS.md 메모의 "소형 모델은 사실을 지어내기 쉽다"가
실제로 나타난 사례다. (요약 8턴 정책의 8개 프로브에서는 지어냄이 관측되지 않았다.)

## 5. 적용한 변경

`ContextManager`와 앱의 기본 정책을 다음과 같이 바꿨다.

| 위치 | 이전 | 이후 |
| --- | --- | --- |
| `ContextPolicy.init` 기본값 | 4,000 / 8 | **7,000 / 64** |
| 시나리오 탭 예산 | 3,000 | **7,000** |
| 시나리오 탭 유지 턴 | 8 | **64** |
| 라이브 세션 | `contextSize-512` / 8 | `contextSize-512` / **64** |

변경 후 같은 34턴 스크립트를 다시 돌려 **8/8**을 확인했다(`LONG_RUN[기본 64]`).
`요약 8턴`/`요약 700` 모드는 비교 실험용으로 앱에 남겨 뒀다.

## 7. UNVERIFIED

- 시뮬레이터 모델 기준이다. 실기기 모델/성능과 같다고 볼 수 없다.
- 정책별 1회 실행이다. 모델 비결정성(같은 질문에 다른 답)을 평균하지 않았다.
- 프로브가 사실을 직접 묻는 형태라, 자연스러운 대화 중의 기억 유지와는 난이도가 다르다.
- 요약이 필요한 100턴 이상 구간은 측정하지 않았다. 그 구간에서는 모델 기반 요약 + 사실 슬롯이 필요하다는
  것이 현재 결론이지만, 실행으로 확인하지는 않았다.
